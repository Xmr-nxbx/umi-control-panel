# 研究笔记

这个目录是开发过程记录，不是使用手册（使用说明在根目录 `README.md`）。
里面记的是「某个开关的语义是怎么确认的、依据来自哪里、哪条结论后来被推翻过」，
目的是让后续开发和排障的人不用重新做一遍实验。

| 文件 | 内容 |
| :--- | :--- |
| `capability-status.md` | 能力状态逐项表 + 跑分与实测记录（powercfg 那一层为什么压不住频率、四档实测数据、模式词表） |
| `hardware-channels.md` | 硬件通道的研究过程：EC 直连、OEM 兜底通道、灯效 HID、固件离线分析，以及 6.3 那组写入原则 |
| `verification-log.md` | 已知问题与待办：每条都标注了「已验证 / 未验证」，未验证的不进代码 |

各文件保留了原 README 的章节编号（第 2 / 6 / 8 节），代码注释里的 `6.11 第十五节` 这类引用
按这个编号来找即可。

## 记录约定

- **只写实测过的东西，并写清来源**：本机抓包、只读转储、OEM 程序集里的常量/枚举、外部项目的记录，
  四类要分开标注，可信度不一样。
- **结论被推翻时保留原文并写明为什么推翻**，不要静悄悄改掉——错误推断的过程本身有价值，
  而且代码注释、测试用例里会引用旧编号。
- **未验证的写操作只登记，不实现**：能力表保持 `blocked`、面板不给按钮，
  做可逆验证时要用户在场（存原值 → 下发 → 回读 → 还原 → 带温度保险）。
- **不做的事**：刷写 BIOS、读写 UEFI 变量/NVRAM、改电池充电门控字节、对内核驱动做地址枚举。
  理由记在 `hardware-channels.md` 6.3 第 8 条。

## 相关工具

研究过程用的工具都在 `tools/`，产物落 `tools/out/`（已 gitignore，不入库）：

```bat
scripts\EC只读自检.bat      &rem 只读验证 EC 通道
scripts\观察EC变化.bat      &rem 21 项语义寄存器，0.5 秒一轮，抓按键这类瞬时变化
scripts\观察EC全表.bat      &rem 125 项全表，2 秒一轮
scripts\观察OEM通道.bat     &rem 同时抓 OEM 命令通道 + EC 全表，用来确认开关语义
```

`tools/` 下带写入的脚本都自带「存原值 → 温度保险 → 还原回读」，并且会自检写操作次数；
只读类脚本（`ec_watch.py`、`ec_fantable_dump.py`、`hid_light_probe.py`、`rom_fv_dump.py` 等）
不做任何写操作。
