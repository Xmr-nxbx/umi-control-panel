# 面板交互与验证边界

## 页面组织

- 总览只展示设备信息、状态与趋势；区分 OEM 硬件档与软件调度档。
- 快速开关控制背光和 Win 锁；未知、断线、过期或未经验证的能力保持禁用。
- 造物者工作区分为风扇、性能、跑分对比三个页签；开启并确认 Turbo 后才允许编辑。
- 灯光按灯效显示有效的颜色、亮度、速度与方向控件；四区键盘与七色色位分开表达。
- 我的方案保存模式、TCC、风扇响应和灯光草稿，不包含功耗墙或风扇曲线。
- 监控展示历史数据；原始字段与通道信息放入诊断，未接入能力如实标注。

## 风扇曲线

### 横轴与编辑

OEM 编辑器按有效节点顺序等距排列，每个标签仍显示设备报告的实际温度，明确标注为非线性刻度。
相同温度的两个节点不合并；仅能上下调整占空比，不能拖动或重写温度阈值。
节点间距至少 48 px，左右各保留半个节点间距及坐标留白；窄屏只在图表区域横向滚动。
数值输入提供另一种编辑方式，CPU/GPU 保留独立草稿，相邻节点限制占空比单调不降。
EC 对照图仍使用线性温度刻度，仅用于读取与比较。

### 恢复默认占空

1. 按当前表名 M1/M2/M3 选择本机 Creator Center 保存的 Gaming/Office/Turbo 默认缓存。
2. 仅读取安装目录 `OEM/CreatorCenter/UniwillService/MyControlCenter/UserFanTables/` 下的固定文件名，
   不接受请求中的文件路径，不复制或分发厂商 JSON。
3. 文件限长 64 KiB；校验双表各 16 个唯一编号、温度和占空范围、连续尾部哨兵与单调性。
   默认首点占空为 0%，末有效点为 100%；允许 GPU 出现重复温度。
4. 选中侧的升温与降温阈值必须逐点匹配当前表，才能填入该侧有效节点的默认占空草稿。
   哨兵、邮箱槽、另一侧草稿、温度阈值和独立输出均保持不变。
5. 已有修改时先确认覆盖；填入不发送硬件命令，仍须点击保存并确认。
   撤销始终恢复最近一次读到的当前表，而不是默认缓存。

这里的默认是**本机厂商保存的缓存**，不是重新从固件生成的出厂认证值。
缺失、损坏或温度阈值不匹配时拒绝填入，不拿当前表、截图估算或其他机型数据替代。
固件升级后缓存可能不再适用，应重新核对。非标准安装目录暂不自动搜索。

不调用 `RESTORE_FAN_SPEED_CURVE_SETTING`：参考实现忽略单侧 Type，会同时覆盖双表及独立输出；
默认缓存刷新还涉及硬件写入，不能作为只读查询使用。
本功能复用既有的单侧占空保存路径，不开放新的硬件写命令。

### 提交与反馈

- 写入携带草稿来源 `expected_name`；后端先读取新鲜表，名字改变或 stale 时拒绝下发。
- 提交期间锁住编辑、切表、默认与撤销；回读逐点匹配后才确认，未确认则保留草稿。
- 服务表回读一致不表示风扇转速已经稳定；输出仍受固件平滑、低速下限及温度保护影响。
- 读取默认期间发生断线、切档或表名变化，不把迟到结果填入新的草稿。

## 性能、灯光与方案

- PL/TCC 草稿不被轮询覆盖；模式变化后要求重新读取，功耗入口与方案、切档互锁。
- 功耗遵守设备报告范围和 PL1 ≤ PL2 ≤ PL4；未回读字段不发送。
- TCC 提交确认同时匹配数值和使能位，即使关闭也不省略数值核对。
- 风扇响应自定义启用时同时确认开关及毫秒数，关闭时恢复自动控制。
- 方案每步等待设备状态确认；已是目标模式时跳过重复切档，失败停止后续步骤且不自动回退。
- 状态读取按请求顺序和时间戳过滤，迟到成功或失败不能覆盖新状态。
- 灯光手动刷新失败保留草稿；背光关闭或未知时不可编辑。海岸灯仍无可靠效果回声，不提供写入。

## 录制边界

录制复用既有订阅，不新建 MQTT 客户端。录制期间抑制收到外部灯效消息所引起的自动键盘刷新，
但主动命令、状态查询及正常调度仍继续，因此不是整机零写模式。
消息记录为 observed、publisher unknown，不凭主题或时间窗推断发布者身份。
录制文件使用唯一名称并独占创建；原始日志不随源码发布。

## 开发与发布验证

Python 测试覆盖默认文件校验、HTTP 路由、写入门禁、录制边界与前端静态结构。
浏览器模拟回归覆盖草稿、默认恢复、并发、断线、延迟确认、方案部分失败及灯光控件。
实际页面使用独立无头浏览器，禁止硬件 POST；默认缓存读取由隔离的只读预览服务验证，
不停止现有面板，不把模拟测试视为新的硬件可逆验证。

发布仅包含源码、测试和必要技术文档；个人设计材料、界面截图、抓图工具、本机配置、凭据、
原始日志及厂商文件保留本地。测试应同时区分开发工作树中的私人资料和实际发布文件集。

升级包含 Python 后端变更时，需要正常重启面板后加载；仅刷新网页不会更新运行中的后端。
